# SageMaker

## 機械学習の全体の流れ

1. ビジネス要件
2. データ準備
3. MLモデル開発 <- SageMaker
4. デプロイ
5. モニタリング

## MLモデル開発

1. 目的の明確化: MLでどんな問題を解決したいのか
2. モデリングアプローチの選択: 目的に最適なモデルの種類を選択
3. モデルのトレーニング: トレーニングデータを与えて賢く育てる
4. モデルの改良: HPOなどで潜在能力を引き出す
5. モデルの評価: パフォーマンス分析、解釈性

## モデリングアプローチの選択

- 回帰 (Regression)
  - 何らかの数値を予測する問題
  - 「金額」「量」など
  - 過去のデータから、数値とそれに関連する要因の関係性を学習
- 分類 (Classification)
  - データを「クラス」「カテゴリ」に属するかを予測する問題
  - 「スパムメールかどうか」「病気の有無」など
  - YES/NO: 2クラス分類、3クラス以上: 多クラス分類
- クラスタリング (Clustering)
  - あらかじめ正解のラベルが与えられないデータの中から、似た性質を持つ同士を自動的にグループに分ける
  - 教師データ（正解ラベル）がないため、データの隠れた構造やパターンを見つけることが目的

それ以外でも

- 推薦システム
- 時系列予測
- 自然言語処理
- ...

### アルゴリズム選択の考え方

例: 分類問題はわかったけど、アルゴリズムは何を選べばいいの？

- アルゴリズムとは？
  - データから学習するための手順やルールのこと
  - たくさんのアルゴリズムがあり、得意な問題や性格・使いどころが異なる

アルゴリズム選択のポイント

1. データの量と質
   - 学習データの量は十分か
   - データの次元数（特徴量の数）は多いか・少ないか
   - データにノイズはないか
   - これらの要素によって、上手く機能するアルゴリズムが変わる
2. 求められる予測精度と解釈性
   - 精度と解釈はしばしばトレードオフの関係にある
   - 業種によっては説明責任が重要 -> 解釈性の高いアルゴリズムが好まれる
   - ビジネスで使う場合「なぜこの予測が出たのか」を説明できることが重要な場合もある

経験を積む内に、どのアルゴリズムがどんな問題に向いているかがわかってくる

### SageMaker 組み込みアルゴリズム

多くの機械学習アルゴリズムは、

- 数学的な背景が複雑
- 効率的に実装するには、専門的な知識と多くの時間が必要

SageMakerは、機械学習のプロセス全体をサポートしてくれる、統合サービス。
代表的な **組み込みアルゴリズム** が使える

- 線形学習
- XGBoost
- LightGBM
- 画像分類
- 物体検出
- 時系列予測

### 組み込みアルゴリズムのメリット

1. 環境構築の手間が省ける
  - 依存関係や環境構築 (プロビジョニング) の手間がない
  - 依存関係内のバージョンが合わない、ライブラリがインストールできない等の悩みがなくなる
2. アルゴリズムの実装不要
  - 自分でアルゴリズムのコードを書く必要がない
  - データさえ用意すれば、すぐに試すことができる
3. 最適化済みで高性能
  - 大量データや分散学習にも対応

## モデルのトレーニング

- トレーニングデータを与えて、モデルがパターンやルールを自動的に学習するプロセス
- データセットを3つの部分に分割することが一般的
  - 過学習を防ぎ信頼できるモデルを作るためには、データの分割は鉄則
    - 学習データ (Training Data): モデルの学習に使用。60-80%程度が一般的
    - バリデーションデータ (Validation Data): 学習の進捗やハイパーパラメータの調整に使用。10-20%程度が一般的
      - 汎化性能：未知のデータに対してどれだけ正確に予測できるかを示す指標
    - テストデータ (Test Data): 最終的なモデルの性能評価に使用。10-20%程度が一般的
      - リリースした時の実際のモデルの性能に近い指標

### SageMakerでのトレーニングジョブの実行

SageMakerを使うと、複雑なインフラ管理・環境構築の手間を省いて、トレーニングジョブを簡単に実行できる

1. 学習データの準備とアップロード
  - 通常はS3にアップロード
2. 学習スクリプトの準備
  - 組み込みアルゴリズムを使う場合は、スクリプト不要
  - カスタムアルゴリズムを使う場合は、トレーニングスクリプトを用意
    - SageMakerのスクリプトモードを使うと、通常のPythonスクリプトでトレーニングコードを書くことができる
3. コンテナイメージの選択
  - 組み込みアルゴリズムを使う場合は、SageMakerが提供する既成のコンテナイメージを指定
  - カスタムアルゴリズムを使う場合は、自分でコンテナイメージを作成して指定
4. トレーニングジョブの作成・起動
  - 使用するアルゴリズム（組み込み or カスタム）
  - 学習データの場所 (S3 URI)
  - インスタンスタイプ
  - ハイパーパラメータ: 学習率、エポック数、バッチサイズなど
  - 出力データの場所 (S3 URI): モデルアーティファクトやトレーニングのログが保存される場所
5. トレーニングの実行とモニタリング
  1. 指定されたインスタンスを用意
  2. コンテナイメージをダウンロード
  3. トレーニングスクリプトを実行
    - 組み込みアルゴリズムの場合は、SageMakerが提供するトレーニングコードが実行される
  4. トレーニングの進捗やログをCloudWatch LogsやSageMakerコンソールでモニタリング
6. モデルアーティファクトの保存
  - トレーニングが完了すると、指定したS3バケットに自動的に保存される
  - 次のデプロイや評価のステップで、モデルアーティファクトが利用される

### SageMaker Managed Warm Poolsによるトレーニングの効率化

- トレーニングジョブの起動時に、すぐに利用できるインスタンスをプールしておく機能
- 特徴量やハイパーパラメータのチューニングなど、複数のトレーニングジョブを連続して実行する場合の待ち時間を大幅に削減
- Warm Poolsを設定すると、トレーニングインスタンスが常に一定数プールされ、トレーニングジョブの起動時にすぐに利用できる状態になる
- 結果としてモデル開発のイテレーション（試行錯誤）が高速化される

## ハイパーパラメータチューニング

- パラメータの種類
  - モデルパラメータ: 学習プロセスで自動的に学習されるパラメータ
    - 線形回帰： 回帰係数、切片など
    - NN： 重み、バイアスなど
  - ハイパーパラメータ: モデルの学習プロセスを制御するパラメータ
    - 学習率： モデルの重みを更新する際のステップサイズ
    - エポック数： トレーニングデータ全体を何回繰り返して学習するか
    - バッチサイズ： 一度にモデルに入力するデータの量
    - NNの層の数やノード数などの構造に関するパラメータ
    - 正則化パラメータ： モデルの複雑さを制御するためのパラメータ

- ハイパーパラメータ1つでも、モデルの性能が大きく変わることがある

- ハイパーパラメータのチューニングの理由
  - あるモデルでの最適な組み合わせが、別のモデルでは最適であるとは限らない
  - データセットの特性やモデルの構造によって、最適なハイパーパラメータの組み合わせが異なるため、チューニングが必要
  - チューニングを行うことで
    - モデルの予測精度を最大化できる
    - 学習に必要な時間を短縮できる
    - 過学習を防止し、モデルの汎化性能を向上させることができる

### 代表的なハイパーパラメータチューニングの手法

1. 手動チューニング
  - 経験や直感に基づいて、ハイパーパラメータの値を手動で調整する方法
  - シンプルだが、最適な組み合わせを見つけるのは難しい
  - 初学者には、ハイパーパラメータの影響を理解するための良い方法
2. グリッドサーチ (Grid Search)
  - ハイパーパラメータの値の組み合わせを網羅的に探索する方法
  - 全ての組み合わせを試すため、計算コストが高くなることがある
3. ランダムサーチ (Random Search)
  - ハイパーパラメータの値の組み合わせをランダムに探索する方法
  - グリッドサーチよりも効率的に最適な組み合わせを見つけることができる
4. ベイズ最適化 (Bayesian Optimization)
  - 過去の試行結果を元に、次に試すべきハイパーパラメータの組み合わせを賢く選択する方法
  - より少ない試行回数で最適な組み合わせを見つけることが期待できる

### SageMakerの自動モデルチューニング

ユーザーはSageMakerにチューニングの方針を伝える。

- チューニングするハイパーパラメータとその値域
- 最適化したい評価指標
  - 例: バリデーションデータでの損失関数の最小化、F1スコアの最大化など
- 試行するジョブの最大数や、並列で実行するジョブの数などのリソース制限

SageMakerは、内部ではベイズ最適化などのアルゴリズムを使って、効率的にハイパーパラメータの組み合わせを探索する。

## 学習中のトラブルシューティング (1) : 過学習

### 過学習とは

モデルが学習データに対してあまりにも適合しすぎて、未知のデータに対応できなくなっている状態。
学習データのノイズや偶然のパターンまで学習してしまうため、汎化性能が低下する。

- 過学習の症状
  - 学習データに対する精度が非常に高い
  - バリデーションデータやテストデータに対する精度が低い -> 汎化性能が低い

- 機械学習モデルを作る目的
  - 過去のデータから学んだパターンを使って、将来の未知のデータに対して正確な予測をすること

- 過学習が起こりやすい条件
  - モデルが複雑すぎる（パラメータが多すぎる）
  - 学習データが少なすぎる
  - 学習データにノイズが多い
  - 学習を長時間続けすぎる（エポック数が多すぎる）

- 学習曲線で過学習を見つける
  - 学習曲線： 学習の進行度と損失関数の値や精度の関係をグラフにしたもの
  - 学習データとバリデーションデータの学習曲線を比較することで、過学習の兆候を見つけることができる
    - 初期段階: 学習データとバリデーションデータの精度がともに上がる
    - 分岐点: 学習データの精度が上がり続ける一方で、バリデーションデータの精度が頭打ちになったり下がり始める
    - 過学習段階: 学習データの精度が非常に高いのに対して、バリデーションデータの精度が低い状態
  - SageMaker では、トレーニングジョブのメトリクスから学習曲線を確認できる

#### 過学習を防ぐ手法

1. 早期停止 (Early Stopping)
  - 学習の途中で、バリデーションデータの性能が向上しなくなったら学習を停止する方法
  - 分岐点を見つけて、過学習が始まる前に学習を終えることができる
    - 検証データの性能が一定期間向上しない場合に学習を停止する設定が一般的
    - 計算リソースの節約にもなる
  - SageMakerの組み込みアルゴリズムの中には、早期停止をサポートしているものもある
  - カスタムアルゴリズムを使う場合は、トレーニングスクリプト内で早期停止のロジックを実装することも可能

2. ドロップアウト (Dropout)
  - ニューラルネットワークのトレーニング中に、ランダムに一部のノードを無効化する方法
  - ある確率でノードを無効化（例: 中間層を50%の確率で無効化）することで、モデルの過学習を防ぐ
  - ドロップアウトが有効な理由
    - 共依存の防止： モデルが特定のノードや特徴量の組み合わせでしか機能しない状態を防ぐ
    - アンサンブル効果： 毎回異なるノードの組み合わせで学習することで、実質的に複数のモデルを同時に学習しているような効果が得られる
  - ドロップアウトの実装
    - `nn.Dropout(p=0.5)` のように、ドロップアウトの確率を指定して使用する
  - ドロップアウトの注意点
    - ドロップアウト率が高すぎると、モデルが十分に学習できなくなる可能性がある

3. 正則化 (Regularization)
  - モデルの複雑さを制御するための手法。MLの世界では王道
    - 複雑すぎると、細かいノイズや偶然のパターンまで学習してしまうため、過学習のリスクが高まる
  - 正則化は、(予測誤差＋ペナルティ) を最小化するようにモデルを学習させる方法
    - 予測誤差: モデルの予測と実際の値の差を表す指標。例： 平均二乗誤差 (MSE)、クロスエントロピー損失
    - ペナルティ: モデルの複雑さに対して課される罰則。モデルの重みが大きくなりすぎないようにするためのもの
  - L1正則化（Lasso）: モデルの重みの絶対値の合計にペナルティを課す方法
    - 不要な特徴量の重みをゼロにする（不要なものは完全に切り捨てる）効果がある
    - 大量の特徴量がある場合に、重要な特徴量を自動的に選択するのに役立つ
  - L2正則化（Ridge）: モデルの重みの二乗和にペナルティを課す方法
    - どの特徴量も完全にゼロにはしないが、極端な重みを抑える効果がある
    - 一般的に、学習が安定し、バランスよく対応できるモデルになりやすい
  - SageMakerの多くの組み込みアルゴリズムは、L1やL2正則化のハイパーパラメータをサポートしている

### SageMaker Debuggerによる過学習の自動検出

実際のプロジェクトでは「いつ過学習が起きているのか」「どの対策を取ればいいのか」を判断するのは難しいことがある。
SageMaker Debuggerは、トレーニングジョブの実行中に、過学習の兆候を自動的に検出して通知してくれる機能を提供している。

1. 自動的なメトリクス監視
  - トレーニングジョブのメトリクスをリアルタイムで監視
  - 学習中の損失、精度、勾配、重みの分布など
2. 組み込みルール
  - 例： 過学習の兆候を検出するための組み込みルール (Overtraining) が用意されている
3. カスタムルール
  - ユーザーが独自のルールを定義して、特定の条件でアラートを出すことも可能
4. リアルタイムアラート
  - 過学習の兆候が検出された場合、CloudWatchやAmazon SNSを通じてリアルタイムで通知
5. 自動アクション
  - 例えば、過学習が検出されたら、自動的に停止するアクションを設定
